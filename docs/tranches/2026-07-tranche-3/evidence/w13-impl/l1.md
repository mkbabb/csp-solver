## What landed

### pencil-boil (sibling repo, committed + tagged + pushed + published — the one sanctioned exception)

**0.8.0** (`8123f47`, tag `v0.8.0`) — the scheduler re-architecture, `src/vue.ts`:

- The perpetual-rAF spin (`rafId = schedulerRunning ? requestAnimationFrame(schedulerTick) : null`,
  the old :155) is dead. Frame-only steady state now PARKS: `armBeat()` computes the earliest
  active frame subscriber's next boundary (`lastTick + getInterval()`, wall clock),
  `setTimeout` aims at it, the wake lands the writes inside ONE `requestAnimationFrame`
  (`startChain()`), and the tick tail re-parks. Between beats: no outstanding rAF, no
  main-thread frame scheduling.
- `sequence` subscribers keep the continuous rAF chain WHILE they run — `armScheduler()` is the
  one dispatch point (`hasActiveSequence() ? startChain() : armBeat()`); any live sequence
  supersedes the park, completion falls back to it. Transient by construction, per the wave.
- Single-tick invariant (strengthens the old single-chain one): at most ONE pending wake —
  beat timer or rAF, never both. `startChain` clears the timer; `stopChain` clears both.
- PRM + visibility gates carry unchanged, now cancelling whichever wake shape is pending
  (hidden-tab `setTimeout` throttling = a second free layer of the parking the wave names).
  Visibility resume goes through `armScheduler()` (idempotent).
- `schedulerDebugInfo()` gains `parked: boolean`; `chains` still truthfully reads the live rAF —
  a settled boiling page reports `chains: 0, parked: true`. Shape is additive; no consumer breaks.
- Every public signature carries forward byte-compatible.

**0.8.1** (`da51edb`, tag `v0.8.1`) — a gate-tripped fix found by MY OWN trace, not banked in the
wave: 0.8.0 traced at **15.97 frames/s (2 rAF/beat)**. Mechanism (probe:
`probe-raf-pattern.mjs`, pair pattern ~8–17ms + ~110ms sleep): the beat timer aims in
`performance.now()` terms but the tick elapsed frame subscribers on the rAF animation timestamp,
which trails the wall clock by ~4ms — the wake's own tick read `elapsed < interval`, advanced
nothing, and burned a steps=0 retry frame every beat. Fix: frame subscribers elapse on
`performance.now()` — one clock for the beat end to end; sequences keep the rAF timestamp
(they're animations; frame time is their truth). Traced after: 7.98/s.

**Proofs** (`proofs/boil-guard.proof.ts`): harness gained controllable `setTimeout`/`clearTimeout`
stubs (globals, resolved at call time); "armed" now spans both wake shapes; blocks (a)–(f)
re-cut to the beat-park grammar; NEW proof **(g) the sleeping steady state** — no rAF at rest,
exactly ONE rAF per wake, re-park after every tick, sequence supersede-and-fallback, withdrawal
disarms both shapes. Suite: **73 assertions green** (boil-guard 37, frames 7, cache 7,
prebake 9, celestial 13) + `tsc --noEmit` clean. README's two "one rAF chain" claims re-worded;
CHANGELOG entries for both versions.
