## 2. Semver stanza for W-B (breaking → bump the 0.x minor slot)

Under 0.x SemVer the **minor** position carries breaking changes. Removing 7 published exports is
breaking, so the published npm package must advance its minor slot on the next publish.

**Stanza (author into W-B / CHANGELOG):**

> `@mkbabb/csp-solver-wasm` 0.2.0 → **0.4.0** — **BREAKING**. The `full-mirror` feature and its
> `isomorphic` module are excised; the published d.ts drops `Csp`, `SolveConfig`, `SolveStats`,
> `OptimizationMode`, `Ordering`, `PropagationStrategy`, `Pruning` (the generic py-mirror surface).
> The shipped surface is now the purpose-built `sudoku` + `futoshiki` + `assignment` layers only.
> No in-repo consumer is affected — the frontend Worker imports `solveSudoku`/`solveFutoshiki`/
> `generate*`/`solveAssignmentCop` only, never the isomorphic classes (R3 §3, re-confirmed: the lean
> deploy build never compiled the isomorphic surface, and its bytes are byte-identical pre/post —
> §4 below).

Why **0.4.0** and not 0.3.0: the tranche's combined W-B+W-C prune/demotion is the core crate's
**0.4.0** surface (S9/R7a — "with W-B this is the 0.4.0 surface"). Stamping the wasm package to the
same 0.4.0 keeps package and crate versions aligned and, because it advances the breaking (minor)
slot across 0.2→0.4, correctly encodes the breaking removal. **0.3.0 would be defensible in
isolation** (minor bump = breaking pre-1.0), but it desyncs the package from the 0.4.0 core surface
this tranche produces; 0.4.0 is the honest, aligned stamp.

**Hard constraint:** the stamp MUST NOT remain 0.2.0. Re-publishing 0.2.0 with 7 exports removed is a
same-version breaking republish (forbidden). Since CI has no publish step (publishing is out-of-band
via wasm-pack `pkg/`), the stamp only bites at the owner's next manual publish — but the in-tree stamp
must be correct so that publish is honest.

## 3. wasm-crate version-stamp decision (`wasm/Cargo.toml:3`)

Current: `version = "0.2.0"` while the core crate (`csp-solver/Cargo.toml`) is `version = "0.3.0"`.
The wasm package version has lagged the core through 0.2→0.3 (the last publish stamped 0.2.0). W-B
should **re-stamp `wasm/Cargo.toml:3` to `0.4.0`** in the same commit as the excision, tracking the
core's 0.4.0 W-B+W-C surface. This resolves both the lag AND the breaking-bump requirement in one
edit. (The `package.json`/`description` "isomorphic mirror" strings are the S1/§1.3 co-edit list —
they drop with the feature.)
