## 4. `gac/mod.rs` split sketch (R12 half a — the charter premise is partly stale)

**Stale premise flagged:** the charter/synthesis say "split along the `matching.rs` seam (Tarjan SCC half
out)". **Tarjan SCC is already extracted** — `tarjan_scc` lives at `gac/matching.rs:102` (`pub(super)`),
alongside `hopcroft_karp`/`dfs_augment`. `matching.rs` is 173 LOC of value-agnostic graph primitives; the
"SCC half" is already out. So the remaining split of the 555-LOC `mod.rs` is a **different, real seam.**

**Anatomy of `gac/mod.rs` (555 LOC):**
- 1–79: module doc + imports + statics/consts (`GAC_CORE_CALLS`, `next_gac_id`, `GAC_MIN_PARTICIPANTS`, …)
- **81–189 + 549–555: the scratch-pool substrate** — `struct GacScratch<V>` (81-113, 20 buffers),
  `MAX_FAST_INDEX` + `fast_index` (115-139), `impl Default` (141-168), `thread_local! SCRATCH` +
  `with_scratch` (170-189), `resize_tarjan` (549-555). **≈ 130 LOC, one cohesive concern:** value-generic,
  caller-owned buffer pooling.
- 191–548: the Régin propagator pipeline — `propagate_gac_core` (204, pub entry), `propagate_inner`
  (218-509, the ~290-LOC body), `finish_all_consumed` (510-548).

**Recommended split → `gac/scratch.rs`.** Move the ≈130-LOC substrate (the six items above) into a new
`gac/scratch.rs` as `pub(super)` (`GacScratch`, `with_scratch`, `fast_index`, `resize_tarjan`,
`MAX_FAST_INDEX`). `mod.rs` drops to **≈425 LOC**, becoming purely the propagator pipeline; `scratch.rs`
sits beside `matching.rs` as the second "caller-owned scratch" primitive — which is exactly how
`matching.rs`'s own doc frames the design ("every buffer is caller-owned scratch so the core can pool them
across calls"). Clean seam: the substrate references no propagator logic; the pipeline touches the scratch
only through `with_scratch`/field access, so the move needs a `use super::scratch::{…}` line and
`pub(super)` on the moved items — no logic edits. **This is a stronger seam than the stale "SCC half"**
(already gone) and than slicing `propagate_inner`'s Phase-2 SCC-pruning block (444-509), which is tightly
interleaved with live `GacScratch` fields (`s.t_scc`, `s.reachable`, `s.res_adj`) and would fragment one
algorithm mid-body.

**Note:** this is a W-C **sketch for the critique verdict**, not applied in this lane's diff (the sweep and
the split are separable commits; the split touches no visibility the sweep touches).

## 5. `search.rs` waiver vs B&B-half split (R12 half b / Q8) — **WAIVER recommended**

**Anatomy of `search.rs` (504 LOC):**
- 1–65: module doc + consts + `SearchParams` + `Step`
- **66–256: the shared unified kernel** — `pub(crate) struct Kernel` (75), `trait SearchPolicy` (166,
  **private**), `fn search` (182, **private**) — the one skeleton the module doc (lines 6-24) exists to
  describe
- 257–342: the `Feasibility` policy + `pub(crate) fn feasibility_search` (≈85 LOC), behind a `// ---` divider
- 343–504: the `BranchBound` policy + `ScoredSolution` + `pub(crate) fn branch_and_bound` (≈160 LOC),
  behind a `// ---` divider — the candidate "B&B half" at `search.rs:444`

### The split fork, both sides drafted

**FOR a B&B split (`solver/search/branch_bound.rs`, ≈160 LOC out → mod.rs ≈344):**
- 504 > the 500-LOC file budget; the two policies are already visually fenced by `// ---` dividers at 257
  and 343, so the seam is pre-marked.
- `BranchBound` is the larger, most independent half — it carries its own `ScoredSolution` struct and the
  cost-eval coupling that `Feasibility` lacks.
- Precedent exists: `matching.rs` already extracts a sibling primitive with `pub(super)`.

**FOR the waiver (keep search.rs whole) — recommended:**
1. **The split widens internal surface AGAINST the tranche's own grain.** `BranchBound` impls
   `SearchPolicy` and calls `search(...)`; extracting it to a sibling module forces `trait SearchPolicy`
   (166) and `fn search` (182) — **currently private** — to widen to `pub(super)`, and likely `Step` (66)
   too. This lane just *demoted* 12 symbols to shrink surface; a B&B split would *re-widen* three kernel
   internals to enable a cosmetic file cut. Net encapsulation: negative.
2. **One concept, one file — the module's stated design.** The doc (6-24) is explicit: "**one** tree-search
   skeleton — `search` — parameterized by a zero-sized `SearchPolicy`," with `Feasibility` and
   `BranchBound` as the two columns of a single policy table. The "single reason to change" is the kernel
   skeleton; the policies are co-designed leaves of it. Splitting one policy out physically separates it
   from its kernel and its sibling policy — the opposite of the unification the file records replacing three
   near-verbatim DFS functions with.
3. **If a split is ever earned, it's `policies.rs` (both leaves out), not B&B-only.** Pulling *both*
   `Feasibility` + `BranchBound` into `search/policies.rs` while `mod.rs` keeps the `Kernel`/`SearchPolicy`/
   `search` skeleton is the only cut that respects the seam — but it still forces the same `pub(super)`
   widening and buys little at 504 LOC. Not recommended now.

**Recommendation:** record the **single-reason-to-change waiver** (synthesis §1.6.5's default), citing the
`pub(super)`-widening argument as decisive — a split trades a 4-LOC-over-budget cosmetic for a real
encapsulation regression during an encapsulation tranche. `gac/mod.rs` (§4) *does* earn its split (a
genuinely separable substrate, no visibility widening); `search.rs` does not. The critique pass owns the
final Q8 verdict.
