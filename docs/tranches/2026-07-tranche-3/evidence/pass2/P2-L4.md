## 1. Gen vs hand — DECIDED: hand-written (R4/Q3 closed)

The pass-1 premise ("spike `maturin build --generate-stubs`") was **half-void and now fully
resolved by execution**, not omission (this answers crit-P3 C5 / kill K14 directly):

- **maturin 1.12.6 (on the box) has NO stub command** — `maturin generate-stubs` → *"unrecognized
  subcommand"*; `maturin build --help` shows zero stub flag. The feature landed later: PR #3105
  (`--generate-stubs`) merged 2026-03-30, PR #3115 (`generate-stubs` cmd) merged 2026-04-07 → first
  in **maturin 1.13.0** (2026-04-09). CI's `uvx 'maturin>=1.0,<2.0'` resolves **1.14.1**, so the
  capability IS reachable in CI — I ran the real spike on 1.14.1.
- **Without `pyo3/experimental-inspect`** the command hard-fails:
  *"Failed to introspect the built libraries … have you enabled the "experimental-inspect" PyO3
  Cargo feature?"*
- **WITH `experimental-inspect` (pyo3 0.29)** it succeeds but emits a **degraded, type-empty stub** —
  the entire generated `csp_solver.pyi` is:
  ```python
  from _typeshed import Incomplete
  def __getattr__(name: str) -> Incomplete: ...
  ```
  Zero classes, zero functions, zero enums, zero exceptions, zero signatures, no `__all__`. This is
  the documented "incomplete module" fallback; pyo3 0.29's introspection captures none of the
  `#[pyclass]`/`#[pyfunction]` surface (pyo3#5137 tracks the gaps). mypy would treat every symbol as
  `Incomplete` (≈`Any`) — worse than no stub, because `py.typed` would advertise typing that doesn't
  exist.

**Decision: hand-written wins on stated grounds** — not "generation unneeded by omission" (the dead
K14 framing) but *generation is empirically empty at the pinned pyo3 0.29*. The hand stub
(`csp-solver/csp_solver.pyi`, 130 lines, full signatures + `__all__`) is the only path that ships
real types. Revisit generation only if pyo3's introspection matures past #5137 **and** the crate
pins that pyo3 — a future re-spike, not a tranche-III option. The **mixed-layout rejection stands**
(§1.4/S7): the hand stub ships via maturin's pure-Rust auto-detection (`📖 Found type stub file at
csp_solver.pyi` → `csp_solver/__init__.pyi` + auto `py.typed`), zero `[tool.maturin]` config.

## 3. `__all__` — DECIDE: declare it in the stub (settled)

pyo3 0.29 **auto-populates the module `__all__`** at runtime (introspected off the installed wheel):
the inner `.so` exposes a 15-name `__all__`, and maturin's `__init__.py` passes it through
(`if hasattr(csp_solver,"__all__"): __all__ = csp_solver.__all__`). Consequences:
1. **Flag-free stubtest REQUIRES the stub to declare `__all__`** matching that list, or stubtest
   flags `__all__` present-at-runtime / absent-in-stub. The hand stub now declares the exact 15.
2. **Bonus safety:** the stub↔runtime `__all__` cross-check is a *separate* stubtest error class that
   `--ignore-missing-stub` does **not** suppress — so with `__all__` declared, surface **growth** is
   caught **even under** `--ignore-missing-stub`. (This narrows crit-P3 C6: the C6 "can't catch
   growth" hazard is real only for a stub with *no* `__all__`.)

## 4. stubtest wired + injected-drift proof (R4/K15 closed)

Wired into the **py-runtime CI lane** (`.github/workflows/ci.yml`), after `pytest`:
```yaml
- name: stubtest (csp_solver stub vs installed wheel, flag-free)
  working-directory: csp-solver/tests-py
  run: uv run --no-sync python -m mypy.stubtest csp_solver --allowlist stubtest_allowlist.txt
```
`mypy>=1.11.0` added to `tests-py`'s `[dependency-groups] dev` (uv.lock re-synced); the committed
`csp-solver/tests-py/stubtest_allowlist.txt` holds **one** regex, `csp_solver\.csp_solver`.

**Flag-free, NOT `--ignore-missing-stub`.** The only friction under a literal flag-free run is
maturin's pure-Rust layout nesting the compiled extension as the private submodule
`csp_solver.csp_solver` (re-exported via `from .csp_solver import *`, absent from `__all__`). The
one-line allowlist suppresses **only** that private submodule — surgical, not the blanket
`--ignore-missing-stub` (which would also swallow real surface growth). With it, stubtest is
**`Success: no issues found in 2 modules`**.

**Injected-drift matrix (flag-free exit; 1 = caught loud):**

| Injected drift | class | exit |
|---|---|---|
| baseline (no drift) | — | 0 |
| remove a module-level function from stub | surface shrink | **1** |
| remove a class method from stub | member presence | **1** |
| rename a method parameter in stub | param-name | **1** |
| drop a live name from stub `__all__` | `__all__` mismatch | **1** |
| add a module-level symbol at runtime absent from stub (via reverse: stub-lacks) | **surface growth** | **1** |
| restored | — | 0 |

The surface-**growth** row is the one `--ignore-missing-stub` would have silently passed (proven:
same drift under the flag → suppressed to a single `__all__`-only error) — this is exactly the
crit-P3 C6 hazard, now closed by running flag-free.

**Honest limit (documented, not a defect):** stubtest **cannot** catch parameter/return **type
annotation** changes (e.g. `domain: list[int]` → `str`) — Python has no runtime type info, so this
is mypy's job on consumer code, not stubtest's. Verified in both `__module__` configs. Coverage is:
module-level presence (classes/functions/exceptions), `__all__`, class-member presence, parameter
names/arity, exception hierarchy. That is the high-value drift band (futoshiki-re-add, symbol
add/remove) and it fails loud.

**Verified-and-reverted dead end:** I tested whether adding `#[pyclass(module="csp_solver")]` (the
pyclasses report `__module__='builtins'` today) would deepen stubtest coverage. It does **not** —
stubtest recurses into class members regardless of `__module__` (method-presence + param-rename
caught in *both* configs). `module=` is cosmetic-only (fixes `repr(Csp)` → `csp_solver.Csp`),
out of this lane's scope, 8-site churn for zero drift-detection gain — **reverted**. Flagged as an
optional cosmetic follow-up, not a stubtest enabler.

## 5. module-name / stub-stem tripwire (R4 closed)

maturin auto-ships the stub only when the root `<module-name>.pyi` stem equals `[tool.maturin]
module-name`. A future module rename (or stub rename) silently drops the stub **and** `py.typed`
from the wheel — no build error, an untyped wheel ships. Added a CI step (py-runtime lane, before
the build) asserting the invariant:
```yaml
- name: Stub auto-detection tripwire (module-name == stub stem)
  run: |
    mod=$(sed -nE 's/^module-name = "([^"]+)".*/\1/p' csp-solver/pyproject.toml)
    test -f "csp-solver/${mod}.pyi" || { echo "::error::stub … missing"; exit 1; }
```
Verified: passes on `module-name='csp_solver'` (stub present); fails loud on a simulated rename.
