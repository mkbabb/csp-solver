## R6(a) — `awaitTickBeforeActivate` is a NO-OP. **DROP the option; the composable ships branch-free.**

### The proof (code-level, decisive)

`AnswerKeyLaminate`'s activation watch is `{ immediate: true }`
(`src/pencil/sheet/AnswerKeyLaminate.vue:60-87`, the flag at `:86`), with the comment at `:84-85`:
*"the async component can mount with active already true on the very first peek — without this the
initial lay-down (and acquireHold) is missed."* That comment describes the **Sudoku** path, and it
is the whole reason the option is dead.

Trace the three orderings against `watch(() => props.active, …, { immediate: true })`:

1. **Sudoku today (SHIPPED, the hard case).** `App.vue:85-98` `startPeek` sets `peekTouched=true`
   then `peekActive=true` **synchronously in the same tick — no `nextTick`** — against an
   **async** laminate (`App.vue:14` `defineAsyncComponent`). The chunk resolves later and the real
   component mounts with `props.active` **already `true`**; the immediate watch fires with `a===true`
   → `acquireHold` + `render=true` + rAF lay-down. This is the async-resolution case, and it works in
   production. If `{immediate:true}` handles the async mount, it trivially handles any static mount.

2. **Futoshiki today.** `FutoshikiGame.vue:34-36` sets `peekTouched=true`, `await nextTick()`, then
   `peekActive=true` against a **static** laminate (`:22` plain `import`). On the `nextTick` flush the
   laminate mounts with `active=false`; the immediate watch fires the **else** branch (a spurious
   `setTimeout → releaseHold` on a hold never acquired, `AnswerKeyLaminate.vue:77-82`); then
   `peekActive=true` fires the true branch. End state correct — but with one wasted watcher pass.

3. **Futoshiki WITHOUT `nextTick` (proposed unification).** Both refs set synchronously in one tick;
   on flush the static laminate mounts with `props.active` **already `true`**; the immediate watch
   fires `a===true` → lay-down. **Byte-identical end state to Sudoku's proven path**, and it *removes*
   the spurious else-branch pass of case 2.

The `nextTick` was load-bearing **only while the watcher was non-immediate** (the now-stale
`FutoshikiGame.vue:17-21` comment predates `{immediate:true}`). No async-resolution race survives:
for a static import the component is available synchronously; for the async import the immediate watch
reads whatever `active` is at eventual mount (if the user released first, it mounts `false` and no-ops
— correct, and `nextTick` would not change that). **Verdict: NO-OP proven. Delete
`awaitTickBeforeActivate`, `AnswerKeyPeekOptions`, the `options` param, the `nextTick` import, and the
`if (options.awaitTickBeforeActivate) await nextTick()` line.** Both scenes adopt the synchronous
`peekTouched=true; peekActive=true` pattern (Sudoku's current form). The composable then has **zero
behavioral branches** — the D1 seam is closed, not deferred.

Kills K19 (agglomeration) at the code level. The critique's UNVERIFIABLE-as-necessary is resolved to
UNNECESSARY.

## R6(b) — hoist the shared `SolveState` union; type the composable against it.

`games/sudoku/types.ts:11` and `games/futoshiki/types.ts:16` are **byte-identical**:
`export type SolveState = 'idle' | 'solving' | 'solved' | 'failed' | 'error'`. The `SolveStats`
interface directly below is **also byte-identical** (`sudoku/types.ts:16-20` ≡
`futoshiki/types.ts:21-25`: `{ backtracks; solutionCount; elapsedMs? }`).

**Ruling.** Create `src/games/shared/types.ts` holding the two identical neutral types. Each game's
`types.ts` **re-exports** them — `export type { SolveState, SolveStats } from '@games/shared/types'` —
so every existing `@games/{sudoku,futoshiki}/types` import site is unchanged (zero consumer churn, no
import cycle: `games/shared/types.ts` has no dependencies). `Difficulty` (sudoku-only,
`sudoku/types.ts:10`) and `Inequality`/`BoardSize`/`VALID_BOARD_SIZES` (futoshiki-only) **stay
per-game** — they are not shared and must not move.

The composable narrows from string-widening to the union:
`solveState: Readonly<Ref<SolveState>>` (import `SolveState` from `@games/shared/types`, same dir).
Both `useSudoku`/`useFutoshiki` return `solveState` typed as the game union, so the narrowing
type-checks unchanged. Closes D2 / R6(b).

## R6(c) / Q7 — the shared-home ruling (three homes, each with a stated charter).

The synthesis §1.5.4 / D5 proposed *"consolidate all shared composables under `src/composables/`."*
Fresh consumer census **refutes the one-home collapse**: the three composables fall into three
genuinely distinct categories. The drift D5 named ("two homes, no rule") is closed by **stating the
rule that assigns each composable its home**, not by merging.

**The rule (evidence-grounded):**

| Home | Charter | Members (post-wave) |
|---|---|---|
| `src/composables/` | app-global cross-domain logic consumed by **games ∩ pencil**, not itself aesthetic substrate | `useTheme.ts` |
| `src/pencil/composables/` | **aesthetic / animation substrate** (owns `pencil-boil` / `pencilConfig` state; a pencil component is among its consumers), regardless of who else consumes it | `celebration.ts`, `useButtonAnimation.ts` |
| `src/games/shared/` **(NEW)** | cross-game shared logic consumed by **both games only**, never pencil | `useAnswerKeyPeek.ts`, `scene.css`, `types.ts`, `constants.ts` |

**Q7 answer — `celebration.ts` IS pencil-domain; the pencil-is-aesthetic framing SURVIVES it.**
Census: `celebration.ts` imports `@mkbabb/pencil-boil` (`mulberry32`) and `@pencil/config/pencilConfig`
(`CELEBRATION`) (`celebration.ts:18-19`); its `register/unregister` half is consumed by a **pencil**
component, `pencil/glyph/HandwrittenGlyph.vue:10` (`registerMurmurCell`/`unregisterMurmurCell`); its
`setMurmurSeed`/`notifyUserEdit`/`resetMurmur` half is consumed by both boards
(`SudokuBoard.vue:11`, `FutoshikiBoard.vue:23`). It is the **celebration/murmur animation substrate** —
aesthetic layer, not shared game logic. Games reaching it is the ordinary **games→pencil** direction
(boundary-legal: `eslint.config.js:18-35` restricts only pencil→games). **`celebration.ts` STAYS in
`pencil/composables/`.** This directly contradicts the synthesis's "move it to `src/composables/`" —
recorded as the corrected disposition.

**`useTheme.ts` STAYS in `src/composables/`** — a genuine app-global (`useDark` wrapper, no aesthetic
substrate) consumed by games (`ControlPanel.vue` ×2) AND pencil (`OptionSelector.vue:2`,
`HandwrittenLogo.vue:4`, `DarkModeToggle.vue:102`). The "one-file dir smell" is outweighed by its being
the real app-global bucket; leave it a singleton with a clear future.

**`useAnswerKeyPeek.ts` + `scene.css` go to the NEW `src/games/shared/`, NOT `src/composables/`.**
They are consumed by the **two game scenes only** — pencil never touches them — so they are
games-domain, not app-global. Colocating them under `games/shared/` (a) keeps them in the games
subtree, (b) keeps `scene.css` beside the composable it pairs with, and (c) is boundary-clean: the
cross-game rules match only `@games/sudoku*` / `@games/futoshiki*` (`eslint.config.js:47-53,70-78`), so
`@games/shared` is importable by **both** games and by neither-imports-the-other. No eslint change is
required for `games/shared/` to exist.

**`useButtonAnimation.ts` (adjacent, out of charter).** Consumed only by the two games' ControlPanels,
never pencil — by the rule it is games-shared-eligible. But it is an 11-line generic press-flag timer
that reads as button-aesthetic, and it is not in this lane's charter. **Deferred to W-F/owner**; noted
only because the rule illuminates it.

**Recommended (optional) boundary tightening:** add an eslint block making `src/games/shared/**` unable
to import `@games/sudoku*` / `@games/futoshiki*` (keep the shared layer game-agnostic). Nothing violates
it today — `useAnswerKeyPeek` takes a structural `target`, importing neither game — so it is a tripwire,
not a fix. Include-or-drop is the owner's KISS call; I lean include (one config block, ~10 lines).

Closes R6(c) / Q7.

## R6(d) — `.board-cells` guard → shared constant + contract note.

The magic string `.board-cells` is a **runtime contract** between two producers and one consumer:
- producers: `SudokuBoard.vue:372` and `FutoshikiBoard.vue:421`, each `class="board-cells grid"` on
  the `role="grid"` cell container (verified: neither element has an existing `:class` binding).
- consumer: the K-peek keydown guard `t?.closest('.board-cells')` (today at `App.vue:124` +
  `FutoshikiGame.vue:75`; after the extraction, once inside `useAnswerKeyPeek`).

If a board renames the class, K-peek exemption silently no-ops for that board (D4).

**Ruling.** Add `src/games/shared/constants.ts`:
`export const BOARD_CELLS_CLASS = 'board-cells'` with a contract comment — *"every board's cell-grid
container MUST carry this class or the K-peek focus-exemption (useAnswerKeyPeek) silently breaks."*
The composable guard consumes it: `` t?.closest(`.${BOARD_CELLS_CLASS}`) ``. Both boards bind the
producer to the same constant — change `class="board-cells grid"` → `class="grid"` +
`:class="BOARD_CELLS_CLASS"` (Vue merges static + dynamic `class`; the rendered value stays
`board-cells` so each board's scoped CSS rule `.board-cells { }` — `SudokuBoard.vue:441`,
`FutoshikiBoard.vue:507` — is unaffected). This makes producer **and** consumer reference one source,
fully closing the lockstep drift rather than papering it. Two one-line board edits + one constant.
Charter-minimum (guard-constant + note) is satisfied; the board-binding is the cheap strengthening that
actually closes it.

**scene.css class-name lockstep (D4, second half).** The shared `scene.css` selectors
(`.app-layout`/`.board-peek-host`/`.controls-card`/`.mobile-board-width`) are a class contract with
both scene templates. Since `SudokuGame.vue` and `FutoshikiGame.vue` are byte-mirror scenes, drift risk
is low; disposition is a **documented contract** (a header comment in `scene.css` listing the required
class names), not a mechanism — proportional to the risk. No constant extraction for these (they are
CSS-only, no runtime querySelector).

Closes R6(d) / D4.
