## wasm pkg target caveat (concurrent-lane integration)

`csp-solver/wasm/pkg` is gitignored and rebuilt by the concurrent Rust lane. During this session it was observed to flip from `--target web` (glue with `__wbg_init(module_or_path)` + `instantiateStreaming`; wasm 87,853 B) to `--target bundler` (glue `import * as wasm from "./..._bg.wasm"` + zero-arg `init()`; wasm 87,282 B). The frontend worker + `vite.config.ts` are written for the canonical `--target web` (Makefile/README) — `?url` asset import + `init({module_or_path})`. A `--target bundler` pkg breaks the worker at both compile time (`import init` has no default export) and runtime (namespace `.wasm` import unsupported by vanilla Vite → worker module fails to evaluate). Both gates (build + 18/18 e2e) were verified green against a locally-rebuilt `--target web` pkg. The gate lane's authoritative `--target web` rebuild restores this. **Action for the gate lane: ensure the wasm pkg is rebuilt with `--target web` (per `csp-solver/wasm/Makefile`), not the wasm-pack default (`bundler`).**
