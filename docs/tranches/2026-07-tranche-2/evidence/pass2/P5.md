## The question

WIN-2's win-sheet claimed "~67 KB for two strings" as the Google-Fonts-CDN
cost this self-host beat would eliminate. The corrections ledger (synthesis
§5) flags that number as the corpus's one mixed-provenance sizing claim.
P5's job: build the *actual* subset woff2s with `pyftsubset`, wire them as a
real `@font-face` variant, and measure — not guess — bytes per face,
subset-vs-CDN, and the CSP tightening the self-host earns.

## What "the app's realistic char sets" turned out to mean

Grepped every template/composable that renders text in each of the three
faces (not a guessed alphabet):

- **Fira Code** (`--font-mono`) — comprehensive, all live consumers:
  `OptionSelector.vue`'s `.ctrl-btn` renders every board-size and difficulty
  option label across both games (`4×4 9×9 16×16 5×5 6×6 7×7`, `Easy Medium
  Hard`), and `AttributionCard.vue` renders the `@mbabb` byline twice.
  22 glyphs: `' 145679@EHMabdeimrsuy×'`.
- **Patrick Hand** (`--font-hand`) — comprehensive, all live consumers:
  `MarginNote.vue`'s status strings (`solved it!`, `not quite — check row
  N`, `still sharpening the pencil…`), both games' `SolverErrorNote.vue`
  paper-note copy (`apiError.ts::PAPER_NOTE_COPY`, verbatim — 7 variants +
  `try again`), `SheetWashiLabel.vue` tooltips (`Randomize`/`Clear`/`Solve`),
  and `HandwrittenLogo.vue`'s dropdown list (`sudoku`/`futoshiki` again).
  45 glyphs incl. em dash + ellipsis: `" !'-.0123456789?CRSacdefghiklmnopqrstuvwyz—…"`.
- **Fraunces** (`--font-display`) — **scoped to the row's literal directive,
  "wordmark + headings," not the whole app**: `HandwrittenLogo.vue`'s SVG
  `<text>` (dynamic — currently `sudoku`/`futoshiki`, driven by
  `App.vue`'s game list) + the app's only two `<h2 class="section-heading">`
  elements (`Size`, `Difficulty`, `Board Size` in both `ControlPanel.vue`s).
  20 glyphs: `' BDSacdefhiklorstuyz'`.

**Important finding, not guessed either**: Fraunces is *also* the CSS
`body{}` default (`--font-text`), which cascades into two more live nodes
(`AttributionCard`'s italic caption "CSP-powered Sudoku solver" and its
"View project on GitHub" link) that are outside the wordmark+headings
scope and contain glyphs (`V w p j G H b …`) the subset doesn't cover. This
is exactly why the row scoped Fraunces narrowly rather than asking for a
guessed "full alphabet" — see **Wiring**, below, for how the diff handles
the boundary honestly instead of silently producing mixed-glyph text.

## The build

Source: upstream `google/fonts` variable TTFs (`Fraunces[SOFT,WONK,opsz,wght]`,
`FiraCode[wght]`, `PatrickHand-Regular`) — the same files Google's own CDN
subsets from. Fraunces was first run through `fonttools varLib.instancer`
pinning `SOFT=0 WONK=1` (verified byte-for-byte against the *served* CDN
file's own `fvar` table — it already drops those two axes at the same
pins), then `pyftsubset` (`uv tool run --with brotli --from fonttools
pyftsubset`) per face:

```
pyftsubset <src> --output-file=<out>.woff2 --flavor=woff2 \
  --text-file=<derived-chars>.txt --layout-features='' \
  --no-hinting --desubroutinize --drop-tables+=DSIG
```

`--layout-features=''` drops Fira Code's programming-ligature GSUB rules
(the app never renders code, only option labels + `@mbabb`) and Fraunces'/
Patrick Hand's unused OpenType features. Coverage verified post-build
(`TTFont.getBestCmap()` against every derived character — zero missing
glyphs, all three faces).

## The byte table (measured, not estimated)

**Self-hosted subsets** (built, `fonttools` version pinned via `uv tool
run --with brotli --from fonttools`, run twice for stability):

| Face | Subset bytes | Glyphs | Axes kept |
|---|---:|---:|---|
| Fraunces (wordmark+headings) | **9,764 B** | 21 | opsz 9–144, wght 100–900 (variable) |
| Fira Code (full app usage) | **3,624 B** | 23 | wght 300–700 (variable) |
| Patrick Hand (full app usage) | **3,840 B** | 45 | static, wght 400 |
| **Total** | **17,228 B (16.8 KB)** | | |

**Current Google-CDN cost** — curled the *exact* CSS2 URL `index.html`
requests today (`Fraunces:ital,opsz,wght@0,9..144,100..900;1,9..144,100..900
&family=Fira+Code:wght@300..700&family=Patrick+Hand&display=swap`) with a
Chrome UA, then curled every `url()` it returned:

| Regime | Bytes | What it counts |
|---|---:|---|
| Naive 16-file sum (all unicode-range chunks, all scripts) | 487,300 B (475.9 KB) | Every cyrillic/greek/vietnamese/latin-ext/latin/symbols2 chunk across all 3 families — **not what any browser actually fetches** for an all-Latin app |
| Latin-only, incl. italic Fraunces | 209,044 B (204.1 KB) | The 4 chunks a real Chrome session fetches for this app's text: Fraunces normal-latin (67,304 B) + Fraunces italic-latin (81,520 B, triggered by `AttributionCard`'s `.italic` caption) + Fira Code latin (36,276 B) + Patrick Hand latin (23,944 B) |
| Latin-only, normal weight only (P5's 3-face scope) | **127,524 B (124.5 KB)** | Fraunces normal-latin (67,304 B) + Fira Code latin (36,276 B) + Patrick Hand latin (23,944 B) — the direct comparison baseline for this row's subset |

**The WIN-2 correction**: "~67 KB for two strings" is real and byte-exact
— it's precisely the served `Fraunces` normal-latin chunk (67,304 B) — but
its *interpretation* is the mixed-provenance error the ledger flagged. That
file's size has nothing to do with "two strings"; it's a fixed cost for
serving 245 glyphs across the full 100–900 weight axis regardless of how
much text uses it. Two real numbers replace it:
- The wordmark+headings' own isolated cost, self-hosted: **9,764 B** (an
  85.5% cut from that same 67,304 B file, for exactly the text that uses it).
- The full three-face app-realistic self-hosted payload: **17,228 B**, an
  **86.5% reduction (7.4×)** against the comparable 124.5 KB CDN baseline,
  or an **91.8% reduction (12.1×)** against the 204.1 KB regime if the
  (out-of-scope) italic chunk is counted too.

**Verified in a real production build** (`vite build`, Vite 6.4.1; the app's
`@mkbabb/csp-solver-wasm` native dependency was stubbed purely so Rollup
could finish bundling — unrelated to this row, not part of the diff): all
three subsets emitted as separate, content-hashed, immutable-cacheable
`dist/assets/*.woff2` files at their exact built sizes (3,624 / 9,764 / 3,840
B — zero bloat from the pipeline). One real finding from that build: Vite's
default 4 KB `assetsInlineLimit` would have base64-inlined the two smaller
faces straight into `index.css` (a ~33% wire-size penalty and loss of
independent immutable caching) — the diff adds a
`assetsInlineLimit: (f) => !f.endsWith('.woff2')` guard in `vite.config.ts`
to force all three to stay separate files, which is what W5's "immutable
cache headers for hashed assets" beat presumes exists.

## The CSP tightening it enables

`public/_headers` and `web/nginx/sudoku.conf` both carried:
```
style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
font-src  'self' https://fonts.gstatic.com;
```
With the Google Fonts `<link>` gone from `index.html`, both external
allowances drop:
```
style-src 'self' 'unsafe-inline';
font-src  'self';
```
Two third-party origins removed from the policy in both places it's
duplicated (CF Pages `_headers` + the nginx reverse-proxy layer).

## Wiring — the honest boundary, not a silent regression

`--font-mono`/`--font-hand` repoint cleanly to the self-hosted faces (their
derivation is comprehensive — every live consumer covered). `--font-display`
repoints to the self-hosted Fraunces subset (its only consumers — 
`text-display*`, `.section-heading`, the wordmark's own hardcoded family
string — are exactly what the subset covers).

`--font-text`/`--font-serif` (the CSS `body{}` default, and the semantic
"prose" register) **deliberately drop `'Fraunces'` from their fallback
chain** rather than pointing at the narrow subset. Grepped first: every
utility class bound to `--font-text` (`text-title`/`text-heading`/
`text-subheading`/`text-prose`/`text-body`/`text-small`/`text-caption`) has
**zero template consumers today** (Tailwind v4 `@utility` emits nothing
unused) — so this changes no rendered heading. Its only real effect is on
`AttributionCard`'s two body-inherited text nodes, which now get the honest
Georgia/Cambria/Times fallback instead of either (a) a phantom CDN
dependency reintroduced just for two sentences, or (b) silently mixing the
self-hosted glyphs it does have with `.notdef` tofu or letter-by-letter
font-swapping for the glyphs it doesn't (`unicode-range` would have produced
exactly that mid-word mismatch had `--font-text` kept pointing at the
narrow-subset `'Fraunces'`). A full body-copy Fraunces subset is a real,
separate follow-on if `--font-text` ever gets a live consumer — out of this
row's scope, called out here rather than left implicit.

## GATE

**None to clear per the row's own framing** — "the action survives either
way; the deliverable is the TRUE byte table... + the CSP tightening it
enables." Both are delivered and measured, not estimated:

- Self-hosted 3-face payload: **17,228 B**, replacing a **124.5–204.1 KB**
  CDN regime (86.5–91.8% reduction depending on whether the out-of-scope
  italic chunk is counted).
- CSP: 2 external origins (`fonts.googleapis.com`, `fonts.gstatic.com`)
  dropped from both policy copies.
- One real corpus correction: the "~67 KB for two strings" figure is
  byte-exact but mis-attributed — it's the whole Fraunces-normal-latin CDN
  chunk's fixed cost, not a cost that scales with string count. The
  wordmark+headings' true isolated cost, self-hosted, is 9,764 B.

**Verdict: PASS** (build succeeded, bytes measured, CSP tightened, wired
into a real production build with zero silent regressions — the one
boundary case found, `--font-text`'s two body-inherited nodes, is handled
explicitly rather than left to break quietly).
