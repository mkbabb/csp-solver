## The question

Is a `propagate`-only worker op + graphite-mark rendering feasible inside the KISS bar? (`SolverRequest` was solve/generate only — verified; `wasm/src/sudoku.rs` had no propagate export — verified, added here.)

## Gate verdict: **PASS → BOOK for tranche III** (with two named design decisions, below)

- Protocol round-trip: **works, 6/6 harness checks green** (masks correct, entry narrows peers, UNSAT clears, erase restores).
- Rendering: **reads as pencil-soul** (screenshots `p4-shots/01–07`; judgment below).
- KISS: **+265/−6 across 9 files, zero new dependencies**, rides the existing worker/glyph/config infrastructure end to end.

## The build — two halves

**(a) Protocol.** `propagateSudoku(board, n) → Uint32Array` added to `csp-solver/wasm/src/sudoku.rs`: pins givens with the same permanent `Domain::restrict_to` move `solve_with_given` opens with, runs `csp.propagate()` (AC-3 auto-selected — `create_sudoku_csp` finalizes), returns one u32 candidate-bitmask per cell (bit v ⇔ value v survives; n=5's 25 values still fit). Contradictory boards throw a typed `UNSAT` coded error, never a half-propagated buffer. Zero search, no node budget. Wire: new `kind: 'propagate'` request/response in `protocol.ts`, worker handler (transfers the mask buffer), `useSolver.propagateBoard()`, `UNSAT` added to `SolverErrorCode` + the worker's pass-through.

Semantics note: the marks are **GAC-strength** (`AllDifferent::revise_impl` = singleton elimination + Régin Hall-set pruning above the live gate), strictly tighter than human peer-scan marks — measured below, and the root of the design finding.

**(b) Rendering.** `useSudoku` debounce-watches `values`/`boardGeneration` (150 ms), round-trips propagate, derives `pencilMarks: Record<pos, number[]>` (empty cells only; cells with a full untouched domain suppressed as noise; stale-shape guard on size switch; last-write-wins seq guard; UNSAT/worker-fault → marks clear silently — marks are a courtesy, never an error surface). `SudokuCell` renders an n×n mini-grid in the classic convention (value v at slot v, so position encodes value at any mark size), each mark a hand-drawn glyph path via `getVariant(toDisplayChar(v), position*31+v)` — per-cell variant scatter, faint graphite (`--color-pencil-graphite`, opacity 0.5, 0.75 under `prefers-contrast: more`), 250 ms opacity-only fade (PRM-safe). `aria-hidden` for the spike. Files: `App.vue`, `SudokuBoard.vue`, `SudokuCell.vue`.

**Soul judgment** (screenshots, light+dark, 4×4/9×9/16×16): the marks read as candidates penciled into cell corners — same hand as the inked glyphs, clearly subordinate in weight, variant-scattered so neighbors never stamp. The UNSAT beat is the best moment of the fiction: write a contradiction and the pencil goes quiet everywhere.

## The design finding — the engine is a *much* better player than the user

Root GAC propagation **collapses a large fraction of served boards to all-singleton domains** — the marks become a verbatim answer key. Observed distributions (empty cells by candidate count): 9×9 MEDIUM `{1: 46}` (fully collapsed); 9×9 HARD sample A `{1: 20, 2: 26, 3: 8, 4: 3}` (the good case); HARD samples B/C `{1: 58}`, `{1: 46}` (collapsed — the harness re-rolls until a multi-candidate board lands). The bank's difficulty is measured in backtracks, and GAC at the root eats most of what MEDIUM serves.

So the fiction "the marks ARE the engine's domains" is mechanically true and experientially wrong at full strength: ambient always-on marks would spoil most boards. The **two design decisions the tranche-III booking must answer** (neither blocks feasibility; the protocol op carries the maximum information and every weaker tier derives from it or from a strategy param):

1. **Propagation tier for the fiction** — (a) naive peer-elimination (what a human's marks actually are; client-derivable, ironically needs no wasm), (b) AC-3-sans-GAC (would need a strategy param on the op), or (c) full GAC with singleton styling/suppression.
2. **Ambient vs opt-in** — the product's existing spoiler surfaces (hold-to-peek, the hint tier) are all deliberate acts; marks as prototyped are ambient. The mark layer likely wants the peek/hint grammar (a toggle wearing `SheetWashiLabel`, or marks only after a hint-tier act) rather than always-on.

Also booked with the row: fold candidates into the cell's accessible name (spike is `aria-hidden`), and a futoshiki mirror (same op shape; `futoshiki_api.rs` untouched here).
