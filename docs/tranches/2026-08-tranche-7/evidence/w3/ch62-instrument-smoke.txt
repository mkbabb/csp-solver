§1 · THE GATE, AND WHY A COUNTER RATHER THAN A READING
------------------------------------------------------
`posePaints` admits on five paths it cannot answer and one it can refuse. Every admit is
SILENT, so from outside the app a gate that fired and a gate that never ran look identical —
which is how the class has been pinned three times. One field per exit, per surface:

  exit (current line)   field                  meaning
  :108 no DOM/Image     noEnv                  the no-DOM admit
  :114 decode threw     decodeRejected         the engine refused the decode
  :120 no 2D context    noCtx
  :127 draw/read threw  taintRejected          a tainted canvas
  :125 decoded + empty  refused                THE REAL POSITIVE — the gate firing
  :147 rebake spent     maxRebakesExhausted    admitted a still-blank set past MAX_REBAKES
       rebake asked     rebakes
       set landed       admitted, probed       the denominators that make `refused > 0` readable
       ARM B only       ablatedAdmits          proof the ablation flag took

Line numbers drift; the exits do not. Each counter sits ON its exit, count-and-continue: no
return value, no ordering and no exit moved. The one structural edit is `next.map(posePaints)`
→ `next.map((u) => posePaints(u, surface))`, which also stops the array index being passed as
a second argument to a one-arity function.

Per-surface WITHOUT touching the three call sites (`HandwrittenLogo.vue`, `HandDrawnGrid.vue`,
`DarkModeToggle.vue` are not this wave's files): the key is read off the calling component via
`getCurrentInstance().type.__name`, which the SFC compiler emits in production builds too, with
a per-instance ordinal separating `DarkModeToggle`'s sun and moon stacks. Measured, 20 keys
over five games:
  <game>/HandwrittenLogo · <game>/HandDrawnGrid · <game>/DarkModeToggle · <game>/DarkModeToggle#2


§2 · THE FENCE — `__bakeAdmission` DOES NOT SHIP
-------------------------------------------------
Gated on `import.meta.env.DEV || MODE === "ch62-probe" || MODE === "ch62-ablate"`, written as a
ternary whose live arm owns the only occurrence of the string. Vite substitutes `MODE` with a
literal, so an ordinary build folds the condition to `false` and drops the arm whole.

  $ NODE_ENV=production npx vite build --outDir dist-ch62-plain
  $ grep -rlE '__bakeAdmission|ablatedAdmits|ch62-probe|ch62-ablate|maxRebakesExhausted|ch62ablate' dist-ch62-plain
    ABSENT (clean)

  $ npm run test:prod-shake -- dist-ch62-plain
    [prod-shake] 23 bundle chunk(s); asserting 3 dev-only symbol(s) absent
    [prod-shake] PASS — the dev tuner is fully tree-shaken from production.

  chunks carrying `__bakeAdmission`:
    dist-ch62-plain    0     (NODE_ENV=production, no --mode)
    dist-ch62          1     (--mode ch62-probe)
    dist-ch62-ablate   1     (--mode ch62-ablate)

The ablation is likewise unshippable and, in the ARM B bundle, TOTAL — esbuild collapses the
whole probe to its first branch:
    async function _s(e,n){return cn(n,"ablatedAdmits"),!0}
and the `ablated` flag reads `bs=!0` in ARM B against `ks=!1` in ARM A. Not a runtime hope: the
bundle carries no other path.

A standing gate for this belongs in `scripts/check-prod-shake.mjs`'s FORBIDDEN list — see the
wiring request; that file is not this wave's to edit.

READ THE `blank` ROW — it is the real-positive chain end to end, and the arithmetic closes:
72 refusals over 6 stacks, 12 rebakes (2 per stack, MAX_REBAKES), 6 exhausted admissions
(1 per stack), and every set admitted anyway. Fail open, delay a bake, never wedge a surface.

The first `noctx` attempt nulled EVERY 2d context and the app rendered nothing — no poses, no
census, `NO INSTRUMENT on the page`. Recorded because it is the shape of a bad control: it
removed the subject instead of one of its exits. The refined patch fences on the probe
canvas's own 24x24 detached geometry.

`noEnv` (`:108`) is the one exit no page can force — it needs no `document` and no `Image`,
i.e. a non-browser host. It is wired identically to its four siblings and is UNPROVEN by
execution. Said plainly rather than counted as proven.

§5 · THE PROBE, AND THE ONE SEAM IT CARRIES
--------------------------------------------
`.github/workflows/ch62-probe.yml` — `workflow_dispatch` only, 2 arms × 6 reps, `fail-fast:
false` (a red IS the measurement in ARM B). Setup mirrored, not invented: the lean-wasm build
is ci.yml lane 0's exact ship recipe, the browser half is lane 9's e2e job step-for-step
(node 24 · npm >=11 · npm ci · Playwright cache keyed on the resolved version · `install
--with-deps chromium webkit`). ci.yml's e2e job downloads `lean-wasm-pkg` from lane 0; a
workflow cannot reach another workflow's artifact, so lane 0 is rebuilt here and the twelve arm
jobs download it.

Per rep: the quarantine is overwritten with an inert stub IN THE CHECKOUT ONLY (so the rows red
instead of `test.fixme`, and so the `>=0.13.0` re-entry throw does not fire on its own subject);
the arm bundle is built with `NODE_ENV=production` pinned — `vite build --mode <x>` with NODE_ENV
unset resolves `isProduction: false`, i.e. a dev-flavoured Vue build, a different app than the
one under test; a vacuity guard greps the bundle for the instrument and REFUSES rather than
measuring all-zero counters; the two specs run against that bundle over the throttle config's
documented external-preview path; the census is dumped per engine; a rollup emits one row.

The verdict job computes the conjunction and prints every term's own number beside it:
  RETIRE ⟺ ARM B red ≥2/6 ∧ ARM A red 0/6 ∧ ARM A refused > 0 ∧ all five fail-opens 0
VOID conditions are distinct from DO-NOT-RETIRE and named as such: a short sample, a missing
report, an instrument that reported no surfaces, `ablated !== true`, or `ablatedAdmits === 0`
in any ARM B rep. A void probe is not a pass and not a pinning. The job reds unless the probe
retires, so a dispatch that decided nothing cannot be read off a green checkmark.

THE SEAM, NAMED NOT HIDDEN: the census comes from the workflow's own pass over the same five
surfaces, not from inside the two quarantined specs. Those specs are another executor's rows
this wave and an instrument that needs its subjects edited is an instrument that changes what
it measures. `e2e/ch62-admission.ts::attachBakeAdmission` is written to drop in beside the
existing `attachBakeEvidence` call the day that wave lands; then the reds and the counters come
off the same pages. Until then the census and the red count are same-bundle, same-runner,
same-dispatch — but not same-page.
