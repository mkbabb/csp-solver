§1  THE DEFECT, AT BOTH SITES

wordmark-integrity.spec.ts:179-187 (pre-cut)
    async function settledPoseInk(page, timeout = 15000) {
      let r = await page.evaluate(READ_POSE_INK);
      while (r.top < 0 && Date.now() < deadline) { await page.waitForTimeout(500); … }
      return r;
    }
  The predicate is `r.top < 0` — "is there ink at all". The assertion 70 lines down is
  `inkBoxViolations(r)`, a verdict over the four EDGES of that ink. The poll returns the FIRST
  inked sample, and the bake has two stages (`useRasterStack` captures on `document.fonts.ready`,
  then again when `measure()` re-fits `vbWidth` under a new `cacheKey`). Stage one's bitmap has
  ink. So the poll's exit condition is satisfied by a box that's still being re-fitted, and the
  edge verdict gets computed on it.

theme-bake-freshness.spec.ts:218-227 (pre-cut)
    const unread = (v) => !v || v === "no-ink" || v === "load-failed";
    while ((unread(s.logoInk) || unread(s.gridInk)) && Date.now() < deadline) { … }
  The predicate is "did the two blobs decode". The assertions are a CONTRAST (logo ink vs live
  paper, ≥ 4) and a ΔE (grid ink vs live `--grid-line-color`, ≤ 24) — each read against a live
  cascade value the poll never looks at. Both blobs can decode perfectly while the numbers the
  row rules on are still moving, and that's not hypothetical: see §3.

Same shape both times — the poll waits for the VACUITY TERM and the assertion rules on the
INVARIANT. It's CH-63's discipline defect one level in: not a sleep standing in for a settle,
but a settle predicate aimed at the wrong quantity.

§4  THE RE-CUT, AS LANDED

wordmark-integrity.spec.ts — the settle is the EDGES (`:206`):
    const inkBox = (r) => `${r.W}x${r.H}:${r.top},${r.bot},${r.left},${r.right}`;
    let prev = await page.evaluate(READ_POSE_INK);
    while (Date.now() < deadline) {
      await page.waitForTimeout(500);
      const next = await page.evaluate(READ_POSE_INK);
      if (next.top >= 0 && inkBox(next) === inkBox(prev)) return next;
      prev = next;
    }
    return prev;

theme-bake-freshness.spec.ts — the settle is the CONTRAST READ (`:251`):
    function verdictReads(s) {                       // the two numbers assertAgrees rules on
      if (unread(s.logoInk) || unread(s.gridInk)) return null;
      return [contrast(s.logoInk, s.paper), deltaE(s.gridInk, s.liveGrid)];
    }
    … if (a && b && a[0] === b[0] && a[1] === b[1]) return next;

Three properties, each deliberate:

  1. IT IS NOT A POLL ON THE ASSERTION. `MIN_CONTRAST` and `MAX_GRID_DE` appear nowhere in the
     predicate, and `inkBoxViolations` appears nowhere in the other. A stale bake is TERMINAL
     (it caches under the incoming theme's key and nothing invalidates it again) and a clipped
     box is likewise stable, so both settle on the first quiet window and red AT ONCE. Polling
     until the invariant is satisfied would have been the masking cure; this waits out motion,
     never a verdict.
  2. THE VACUITY TERM KEEPS ITS FULL WINDOW. An undecoded surface is never "settled", so a
     terminal blank still burns the whole 15s and still reds — `no-ink` through
     `inkBoxViolations`, and the estate's unconditional `not.toBe("no-ink")` next door. The
     linux-webkit blank class (CH-62) sees no change in exposure: same deadline, same evidence
     attach, same quarantine call in the same place.
  3. THE LIMIT IS STATED, NOT GLOSSED. One quiet 500ms window is what "stopped moving" means
     here. A re-bake landing after a full quiet window reads as settled to this or any stability
     predicate; bounding THAT needs a causal signal — the `cacheKey` the bake fires on — not a
     longer wait. Both file comments say so.
