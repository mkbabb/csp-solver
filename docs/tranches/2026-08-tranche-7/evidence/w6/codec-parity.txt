§3 — WHAT THE IMPORT COST, AND WHY IT WAS WORTH IT
--------------------------------------------------
The wave's premise — "e2e already imports from `../src/`, so the seam exists" — is true in one
direction only. Pulling `e2e/wire.ts` INTO the app's tsconfig program (which a `src/**` unit
does, by importing it) put the file under `vue-tsc` for the first time, and it reached for
node's `Buffer` while the repo carries no `@types/node` — it's a browser app, deliberately:

  e2e/wire.ts(30,10): error TS2591: Cannot find name 'Buffer'.

CI runs `npx vue-tsc --noEmit` (ci.yml:642), so that is a red build lane, not a born-RED gate.
The cure is the wave's own medicine rather than a shim: `wire.ts` was carrying a FIFTH copy of
base64url (`+`→`-`, `/`→`_`, strip padding) written over `Buffer`, while the app's copy — the
one the codec under test actually uses — goes through `btoa` in `src/lib/base64url.ts`. A
module whose entire reason for existing is that the wire has one spelling had two spellings of
its own envelope. Deleted; `wire.ts` imports `toBase64Url` at all three call sites.

Byte-identity of the two implementations, checked before the swap over 403 inputs — every
latin-1 code point 0..255 in 53 lengths, plus the tagged sudoku and 16×16 bodies:

  cases: 403 divergences: 0

Also cleared while in the file: `CODEC_VERSION` was exported with zero importers (invisible
until a sibling W6 row widened knip's `project` to e2e non-specs). Made private, matching the
codec's own (persistence.ts:139).

DECLARED: `e2e/wire.ts` is named in this executor's task as an import source, not an edit
