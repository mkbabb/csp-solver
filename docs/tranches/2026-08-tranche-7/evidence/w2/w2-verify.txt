A1 — THE PADDING IS SOURCED HONESTLY, AND IT TRACKS.
`useResizeObserver` on `.action-bar` publishes `--action-bar-h` onto `bar.closest(
'.controls-card')` from `getBoundingClientRect().height` (border box, not `contentRect`)
plus the card's computed `padding-bottom`. Read at four rungs, published vs re-derived
truth:

                          published   computed scroll-pad   truth (ceil(barH+pad))
  1440×900  (p-5, 20px)   86px        86px                  86px   barH 65.16 / 65.14
   900×900  (py-1.5, 6px) 71px        71px                  71px   barH 64.02
  back 1440               86px        86px                  86px
  390×844 dock, open      69px        69px                  69px   barH 62.94

  THE STALENESS QUESTION, ASKED AND ANSWERED. The card's padding-bottom is a Tailwind
  class that flips on the row regime (`GameScene.vue:167` — `p-5` ⇄ `px-2 py-1.5`), so it
  is a term the observer doesn't watch. It doesn't go stale anyway: the bar's WIDTH changes
  across that same regime cross, the RO fires on it, and the callback re-reads the padding.
  Measured across 1440→900→1440 in both engines — published equals truth at every rung.
  This is the one thing the `--fold-bottom` lesson would have predicted going wrong, and it
  doesn't.

A2 — THE CONDITIONAL IS CORRECT, AND IT IS NOT PERMANENT.
`ribbonCovered = portraitDock && !drawerInert`, where
`drawerInert = !drawerOpen && phase === 'idle'`. Measured at 390×844, both engines:

  drawer SHUT   inert attr ABSENT, `el.inert` false, all four verbs tabIndex 0 and each
                one TAKES FOCUS (Undo, Redo, Reveal-hint, peek — `document.activeElement
                === btn` true for all four)
  drawer OPEN   inert attr PRESENT, `el.inert` true, focus refused (activeElement falls
                to body), count still 4
  RE-SHUT       inert attr absent again, focus takes again

  So it's `undefined`-gated as the estate's GameCard idiom wants — absent at rest, never
  present-and-false — and it's a state, not a life sentence. The glide window is covered
  too: `phase !== 'idle'` keeps the ribbon frozen through opening AND closing, which is the
  right read, since a half-covered control is the same defect measured mid-flight.

  THE TONGUE IS A SIBLING, verified rather than reasoned: `.drawer-tab`'s parent is
