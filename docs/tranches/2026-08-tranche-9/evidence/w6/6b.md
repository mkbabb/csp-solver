### Why the two population canaries exist

A `tsc` whose `include` stops matching exits 0 in cheerful silence — a directory rename does it.
This workflow already has two instances of the class: the theme-selector census went vacuous by
population, and the lane-membership corpus was name-shaped until T9-W5 §5.4. So each new
typecheck step counts its own program (`--listFilesOnly`) before trusting its verdict: `e2e/`
owes ≥30 files (36 at this wave), the relay owes 2.

Both `|| true`s in those steps are load-bearing rather than defensive habit, and the first
attempt proved it: an empty `include` makes tsc EXIT 2, `grep -c` PRINTS 0 while EXITING 1, and
under `set -o pipefail` either one killed the step before it could print its diagnostic. A silent
red is only marginally better than a false green. Both readings are in
`gates-ci/canary-e2e-population-RED.txt`.

## 4. The decisions that were not obvious

**No `@types/node`.** `e2e/` calls six node functions and reads two globals. The package is not
installed, and installing it is not a free act: it is a **lockfile** edit, and because
`tsconfig.json` declares no `types` field, every `@types/*` on disk becomes ambient in the APP's
typecheck too — `process` and `Buffer` would silently join `src/**` browser code. So the surface
is declared in `e2e/node.d.ts`, in the exact shapes the estate calls, the same discipline
`relay.ts` keeps for the Cloudflare runtime one directory over. Narrow is not a compromise here:
`readFileSync` without an encoding does not compile at all until someone says what they meant.
The widening remains available to the chair and the seam is written out (`handoffs/6b-2.md`).

**The relay gets its own eslint config, not a widened one.** ESLint's flat config has ONE base
path — the directory holding the config file — so `eslint .` under `web/frontend` answers
*"located outside of the base path"* for a sibling package and lints nothing. Measured, not
assumed. `web/relay/eslint.config.mjs` re-exports the frontend's config (one law, one file) and
gives it a base path over there; `lint:relay` `cd`s in and reaches the binary the way
`wrangler.toml`'s own header documents for wrangler and vitest. The `.mjs` extension is not
cosmetic: as `.js` in a package with no manifest, node reparses it and warns, walking all the way
up to `$HOME/package.json` for advice.

**Both relay files are knip `entry`, and what that does not buy is stated in `knip.json`.** Knip
does not grade unused exports on an entry file, so `relay.ts`'s export surface is not under the
exports rule the way `src/**` is. The alternative — make the test the only entry and let it pull
`relay.ts` in — does not work: knip reports `../relay/relay.ts` unused under it
(`gates-relay/knip-widen-probe-1-testfile-orphan.txt`). What the pair does buy is the dead-FILE
law over the relay directory, proven by plant.
