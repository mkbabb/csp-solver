# 6B-2 → the five config files at `web/frontend/` root — the same hole, one directory up

§6.2's subject was `web/frontend/e2e/` and `web/relay/relay.ts`. Closing them exposes a third
member of the same family that the fence does not name, so it is measured and handed over rather
than widened into silently.

`web/frontend/tsconfig.json`'s `include` is `["src/**/*.ts", "src/**/*.tsx", "src/**/*.vue",
"env.d.ts"]`. That leaves **five first-party TypeScript files at the package root under no
typecheck at all**:

```
vite.config.ts   vitest.config.ts   playwright.config.ts
playwright-golden.config.ts   playwright-throttle.config.ts
```

They are LINTED — `eslint .` reaches them, since the flat config's base path is this directory.
They are not formatted: `npm run lint` names `src/ scripts/ ../../scripts/ ../relay/`, and the
package root is not on that list. And they are type-checked by nothing at all.

## What is actually wrong in there, measured

Probed with a throwaway `tsconfig.__probe.json` (`extends ./tsconfig.json`, `types: []`,
`include: ["*.config.ts", "env.d.ts", "e2e/node.d.ts"]`), run once and deleted. Two findings are
real and node-independent:

### 1. `playwright-golden.config.ts:84` — the PRM void, third site

```
playwright-golden.config.ts(84,5): error TS2769: No overload matches this call.
    Object literal may only specify known properties, and 'reducedMotion' does not exist in
    type 'UseOptions<PlaywrightTestOptions & CustomProperties<unknown>, ...>'
```

Same mechanism this lane named at the two `e2e/` sites: at `@playwright/test` 1.61.1
`reducedMotion` is not a member of `PlaywrightTestOptions` — the name appears once in
`playwright/types/test.d.ts`, inside `contextOptions: BrowserContextOptions`. The two `e2e/`
sites now carry a cast and a comment saying so; this one does not, because it is out of fence.
`e2e/prm-void-audition.spec.ts`'s step 3 ("update the version in VOID_AT and the comments citing
1.61.1, in the same commit") should collect this file too.

### 2. `vitest.config.ts:75` — `coverage.all` is not an option at vitest 4

```
vitest.config.ts(75,7): error TS2769: No overload matches this call.
    Object literal may only specify known properties, and 'all' does not exist in type
    'CoverageOptions'.
```

The line is `all: true`, and the comment above it reads *"Report every included file, imported by
a unit or not (see the header note)"* — a claim the coverage floor's whole denominator argument
rests on (`vitest.config.ts` header: *"an unimported module must read 0%, because 'collapsed five
modules into one and lost its only caller' is exactly the W2 failure the floor exists to
catch"*). **This lane does not claim the denominator is wrong** — the v8 provider may report the
whole `include` glob by default at v4, which would make the option redundant rather than
load-bearing. It claims only that the estate is asserting a behaviour through an option the
runner's own types do not have, and that nothing has been able to say so.

Whoever takes this should decide it by measurement, not by reading: run
`npm run test:unit:report -- --coverage` and check whether a module with no importer appears in
`coverage/coverage-summary.json` at 0%. If it does, delete the dead option and keep the header's
claim. If it does not, the coverage floor has been grading an import-scoped denominator and
`scripts/check-coverage-floor.mjs`'s baseline needs re-cutting — which is a W5 subject.

### 3. `vite.config.ts` — node surface, NOT a defect

The remaining eight errors are all `existsSync` / `writeFileSync` / `resolve` / `__dirname` /
`process.cwd`. They are artifacts of the probe reusing `e2e/node.d.ts`, which declares only what
`e2e/` calls, by design. `vite.config.ts` needs a wider node surface than the spec estate does.

## The seam, if the chair wants the whole root closed

A `tsconfig.node.json` beside `tsconfig.e2e.json` — same shape, `include: ["*.config.ts"]` — plus
a step in the `frontend` lane. It needs a node type surface first: either `@types/node` as a
devDependency (which is a **lockfile** edit and, because `tsconfig.json` declares no `types`
field, would also make `process` and `Buffer` ambient inside `src/**` browser code — pin
`"types": []` there in the same commit), or a second narrow declaration in the register of
`e2e/node.d.ts`.

This lane chose the narrow declaration for `e2e/` precisely to keep that decision the chair's.
