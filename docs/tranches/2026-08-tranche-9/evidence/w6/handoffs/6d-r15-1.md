# Handoff 6D-R15-1 — the deck's CHOICE walks on a resize (out of fence: `useCarouselGlide.ts`)

Found while measuring R15's re-anchor on the live edge. Orthogonal to R15's anchor and NOT
cured by it; my fence is `GameGallery.vue`'s `guardX` seam and this lives in the glide.

## THE SEAM

`web/frontend/src/pencil/chrome/GameGallery/useCarouselGlide.ts:533-535`

```ts
    if (vp && typeof ResizeObserver !== "undefined") {
      resizeObs = new ResizeObserver(() => jumpTo(currentIndex));
      resizeObs.observe(vp);
    }
```

`jumpTo` writes `vp.scrollLeft = targetScrollLeft(i)` with snap suspended, then re-arms
`scroll-snap-type: x mandatory` on the next rAF (`rearmSnap`, :248-255). On a viewport that just
changed width, the engine's own re-snap after that re-arm lands on a DIFFERENT card. The scroll
it produces reaches `onScroll` (:359) → 90ms debounce → `reportSnap` (:348) → `restingIndex()`
returns 1 → `options.onSnap(1)` → `GameGallery.vue:469 syncFromScroll(1)` → `dismissGuard()`.

## WHY IT MATTERS BEYOND THE RIBBON

The walk is not a ribbon defect — it is the deck silently changing which puzzle is CHOSEN because
the window changed size. The ribbon's dismissal is just the loudest symptom (T9-W3's law: an
`alertdialog` holding focus disappearing unbidden). A reader who rotates the phone lands on a
different card than the one they were looking at, and `announce()` never says so because
`syncFromScroll` speaks the arrival rather than the loss.

## THE LITERAL TEXT TO LAND (candidate — measured as the defect, NOT measured as the cure)

The re-pin must own the position through the engine's own re-snap, the way a glide does. At
`useCarouselGlide.ts:533-535`, replace the observer body with a re-pin that re-asserts after the
re-arm has settled:

```ts
    if (vp && typeof ResizeObserver !== "undefined") {
      // The resize re-pin owns position through the engine's OWN re-snap: re-arming
      // `x mandatory` on a viewport that just changed width lets WebKit settle onto a
      // different card, and `reportSnap` then reports that walk as the reader's choice.
      resizeObs = new ResizeObserver(() => {
        jumpTo(currentIndex);
        requestAnimationFrame(() => jumpTo(currentIndex));
      });
      resizeObs.observe(vp);
    }
```

CAUTION for whoever lands it: a re-pin deferred into a rAF lands AFTER the ResizeObserver
broadcast, which is where `GameGallery.vue`'s guard re-anchor reads. That is exactly why the R15
cure carries a second arm — a `passive` `scroll` listener on the viewport — so the note
re-measures whenever the track moves regardless of re-pin timing. Keep that arm if this lands.

An alternative worth auditioning first: leave the position alone and stop `reportSnap` from
attributing a post-resize settle to the reader (a resize is not a gesture). That is a smaller
claim and needs no rAF.
