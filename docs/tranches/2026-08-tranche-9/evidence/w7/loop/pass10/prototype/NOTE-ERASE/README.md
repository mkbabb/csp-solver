## 4 · Row 4: user- and UA-origin `!important`, and the explicit `done`

**The chromium user-origin route, attempted in the default headless shell.** `bin/ext-probe/` is a three-file MV3 extension (a service worker that calls `chrome.scripting.insertCSS({origin: 'USER'})` with `.margin-note-ink.note-leave-active { animation-duration: 900ms !important }` and a marker custom property, plus a `document_start` content script that sets a marker attribute). `probe.mjs` launches it through `chromium.launchPersistentContext(…, {headless: true, args: ['--disable-extensions-except=…', '--load-extension=…']})` on Playwright's default executable (no `channel`), waits 10 s for a service worker, opens the lane's tree and reads both markers. The transcript and verdict are in §4a below.

**WebKit.** Playwright has no user-stylesheet surface for WebKit (no extension loading, no user-origin injection), so a user-origin plant there is unplantable by construction, and I don't claim a reading. UA origin is unplantable in both engines: no page or automation surface writes the UA sheet.

**What a user-origin `!important` does to the shipped clock (mechanism, per engine).** A user `!important` declaration outranks an author `!important` one, inline included (CSS Cascade 5 §6.2). So `animation-duration: 900ms !important` at user origin beats the hook's inline `!important` write. Vue's fallback timer reads the computed duration (`runtime-dom` `getTransitionInfo`), so the node is held about 900 ms. The fence can't see it, because its read is right: the verb runs, on the document timeline, for 900 ms. Under that sheet the sentence leaves on the user's clock. That's the user's stated preference, not a defect of the erase.

**The explicit `done`, priced in cells against Vue's fallback.** A two-parameter `@leave` (`(el, done)`) takes the clock from Vue (`hasExplicitCallback`). The hook would then own it: `done()` at once when nothing runs, else on the running animation's `finished` promise, with a cancel path for `leave-cancelled`.
