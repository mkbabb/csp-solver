**The mechanism.** Pre-warming. The theme token is in two `cacheKey`s (`HandDrawnGrid.vue:214`,
`HandwrittenLogo.vue:343`; the celestials carry none and never re-bake), so the first flip to
an unseen theme bakes 4 wordmark + 4 grid poses inside the gesture. After `boardDrawnMs`, on
`requestIdleCallback`, bake those 8 for the theme NOT showing and `retain()` them under their
own capture identity—no `urls` swap, no `<html class>` write. The seam exists:
`resolveCssValue(el, prop, fallback)` (`rasterPose.ts:102`) resolves against a given element,
so a detached probe carrying `class="dark"` yields the other theme's 30 custom properties with
no visible flip. Headroom is real: the pose cache is per SURFACE instance, 4 slots each
(`vue.js:471`, refuter's correction)—one slot spent, no eviction.
Serialized: ONE pose per idle callback, never the library's all-at-once burst; yield to input;
abandon and re-queue if a gesture starts. Fallback clause for a cache miss (DPR or box change
between boot and toggle): hold the retained stack through the whirl and re-bake at the first
idle after it—full-quality previous ink for ~1 s, a window W7 must accept in writing first.
The cost is symmetric (dark→light 1,202.4), so "other theme" means exactly that.

**The π obligation.** Identical pose SVGs → identical bitmaps: the pre-warmed stack hashes equal
to the stack a live flip bakes today, per pose, both themes. No new filter (`filterBudget` 9).
