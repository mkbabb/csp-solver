**The mechanism.** Caching, at the zone: a Cloudflare Cache Rule making `.wasm` eligible (it
isn't in the default cacheable-extension list) and, if the owner wants it, the document held at
the PoP with revalidation. `public/_headers` can't do either—it sets browser directives and is
already honoured exactly. Also here: CF Web Analytics injects `beacon.min.js`, the estate's own
CSP blocks it (`requestfailed: csp`)—one console violation and dead bytes in an uncacheable
document per load. The owner switches it off or it stays as it is; the CSP is not loosened.

**The π obligation.** None drawn. `_headers`' security stanza unchanged.

**Prove it on.** the live edge after the next CH-57-gated deploy: `edge-census.sh`, 5 passes, GET.

**Accept.** wasm `cf-cache-status: HIT` with a non-zero `age` on ≥ 4/5 passes; TTFB inside the
HIT band; index.html still revalidates so a deploy is seen at once (verify from ONE response—the
CF domain flaps ~1 min post-deploy).

**It must not.** Let a stale `index.html` pin an old entry hash; add `'unsafe-inline'` or
loosen `script-src`; claim a device millisecond from a curl.
