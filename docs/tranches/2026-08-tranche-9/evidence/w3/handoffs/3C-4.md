# 3C-4 — §3.7 coarse-pointer attribution is a REPAINT, and this wave does not repaint

Lane 3C's fence lists "coarse-pointer attribution MECHANISM (look is W7's — any pixel = declared
DELTA)" under `GameControlPanel.vue`. The attribution surface is not in the panel: it is
`GameBoard.vue`'s `.attribution-tape` (`:1061-1068`), driven by `hoveredPos` / `hoveredAuthor` /
`tapeAnchor` (`:486-520`), fed by `DigitCell`'s `cellHover` emit, which fires from
`@mouseenter` / `@pointerleave` (`DigitCell.vue:226`, `:177`, `:181`).

Held back deliberately rather than for want of room, and the reasons are three:

1. **It paints.** Every other 3C cure measures 0.000px of movement across ~1,138–1,178 rects in
   four states and two engines (`evidence/w3/panel-pi-ablation.txt`). This one mints a visible
   tape where none exists today. The wave's own π law says a cure that moves a pixel declares a
   DELTA and lands with W7; W7 §6 already owns this surface's look.
2. **Nobody is unserved in the accessibility tree.** The tape is `aria-hidden` by its own anchor
   rule and always has been; the coarse route to authorship is the CELL'S OWN NAME
   (`DigitCell`'s `authorName`), which lane 3B corrected this same wave. What a touch reader
   lacks is a SIGHTED affordance — a look question, not a spoken one.
3. The fence's assignment names the wrong file, so landing it would have been out of fence
   either way.

## The seam, so W7 does not have to re-derive it

The whole mechanism is one fallback, in `GameBoard.vue`, and it needs no new emit, no
`DigitCell` change and no new component: a coarse pointer has no hover, but a tap gives FOCUS,
and the board already tracks `focusedPos`.

**`web/frontend/src/games/shared/GameBoard.vue:486`** — replace

```
const hoveredPos = ref<number | null>(null);
```

with

```
const pointedPos = ref<number | null>(null);
// T9-W3 §3.7 / T9-W7 §6 — A FINGER HAS NO HOVER. The tape is raised by `mouseenter`, so on a
// coarse pointer the one surface that names who wrote a digit could never appear at all. A tap
// gives FOCUS, and the board already tracks it, so the coarse arm is the roving tabindex's own
// position and nothing else. Fine pointers are untouched: `pointedPos` is the hover exactly as
// it was, and `isCoarse` is false there.
const isCoarse = useCoarsePointer();
const hoveredPos = computed(() =>
  isCoarse.value ? (pointedPos.value ?? focusedPos.value) : pointedPos.value,
);
```

with `onCellHover` (`:487-489`) writing `pointedPos` instead, and
`import { useCoarsePointer } from "@games/shared/useCoarsePointer";` added to the imports.

`hoveredAuthor` (`:495`) already returns null for your own cells and the unauthored, so a solo
board mints nothing and the tape only appears where a peer actually wrote — which is the same
gate the fine-pointer arm has.

## What the DELTA is, when it lands

A new `.attribution-tape` box over a peer-authored cell on any coarse surface, for as long as
that cell holds focus. It moves no layout (`position: absolute`, `pointer-events: none`) but it
paints, and it will need before/after screenshots at 390×844 and 820×1180, both engines, plus a
re-look at `visual-regression.spec.ts` — solo boards are unaffected by construction, so the
committed goldens should hold, but "should" is not the standard and the sweep is cheap.
