Lane 3C's fence lists "guard-arm double-speak" under `GameControlPanel.vue`. It is not there.
The panel's own two-tap arm (`dealArmed` / `clearArmed`) is already single-voiced and correct:
the sublabel that flips to "sure?" is `aria-hidden="true"` and only the `aria-label` speaks

The DOUBLE-SPEAK is the gallery's destructive-work guard, and it is out of 3C's fence entirely
(lane 3A owns that file this wave).

## The mechanism, stated

`GameGallery.vue:758-768` arms the guard in two channels on the same tick:

1. `sayGuard(\`${guardTitle.value} ${guardSub.value}. Choose keep, or ${guardVerb.value}.\`)`
   → `.gallery-guard-live`, a `role="alert"` (`:950`).
2. `guardEl.value?.focus({ preventScroll: true })` → moves focus INTO
   `role="alertdialog" aria-modal="true" :aria-label="guardTitle"
   aria-describedby="gallery-guard-stake"` (`:885-891`), whose description node is the same
   `guardSub` string (`:896-898`).

Focus entering a dialog makes AT read its name, its description and its role. So the title and
the sub are spoken twice, back to back, and the second reading adds nothing.

## The cure §3.7 names, and the gate that must move with it

"one utterance, not two (drop the redundant channel; the alertdialog's name is the survivor)."

**`GameGallery.vue:759-761`** — replace

```
    sayGuard(
      `${guardTitle.value} ${guardSub.value}. Choose keep, or ${guardVerb.value}.`,
    );
```

with

```
    // T9-W3 §3.7 — ONE UTTERANCE. The focus below moves into an `alertdialog` whose NAME is
    // `guardTitle` and whose DESCRIPTION is `guardSub`, so an armed guard read its title and
    // its stake twice over: once from this region, once from the dialog it hands focus to.
    // The dialog is the survivor — it is the thing the reader is actually inside, and it is
    // the only channel that also carries the verbs. What this region keeps is the half the
    // dialog cannot say, which is the choice on offer.
    sayGuard(`Choose keep, or ${guardVerb.value}.`);
```

**THE GATE MOVES IN THE SAME COMMIT OR THE CURE REDS.** `e2e/a11y.spec.ts:184-197`
(`guardAnnounced`) accepts a cure only if a live region's text CONTAINS the guard's own
`aria-label`, or the ribbon itself carries `role="alert"`/`aria-live`. Trimming the region to
the verbs alone satisfies neither, and three rows go red with it
(`a11y.spec.ts:319`, `:362`, and the helper's other caller).

`e2e/a11y.spec.ts:193` — replace

```
    const key = norm(guard.getAttribute('aria-label')).replace(/[?.!]+$/, '');
    if (!key) return false;
    return [...document.querySelectorAll('[aria-live],[role="status"],[role="alert"]')].some(
      (r) => norm(r.textContent).includes(key),
    );
```

with

```
    // T9-W3 §3.7 — the guard's NAME is the dialog's, and repeating it in a live region was the
    // double-speak. What a live region must still carry is that the guard is ARMED and what it
    // is asking, so the gate reads the VERB the ribbon offers rather than its title.
    const verb = norm(guard.querySelector('.guard-leave')?.textContent ?? '');
    if (!verb) return false;
    return [...document.querySelectorAll('[aria-live],[role="status"],[role="alert"]')].some(
      (r) => norm(r.textContent).includes(verb),
    );
```

## The adjudication the chair owes this row

The region was minted at T5-W3 §3.2 for a stated reason (`GameGallery.vue:428-433`): a prompt
about losing work must not queue behind the deck's polite chatter. That reason survives the
trim — the region is still `role="alert"`, still assertive, still persistent, still says
something on arm. What it stops doing is reciting the dialog's own name back at a reader who is
standing inside the dialog.

The alternative reading — drop the region OUTRIGHT and let the alertdialog be the whole
announcement — is what §3.7's wording most literally asks for, and it is the WEAKER cure: the
`a11y.spec.ts` helper's own comment records that `role="alertdialog"` alone carries no implicit
live semantics (r2 §H2), so an engine that does not announce the dialog on focus would leave
the arm silent. Recommended: the trim above. Ruling is the chair's.
