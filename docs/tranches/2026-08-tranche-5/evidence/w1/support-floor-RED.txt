--- 4 · WHAT THE FLOOR ACTUALLY IS (derived, not chosen) --------------------

The row says "derive from what the estate already requires". Four independent
constraints were measured off the tree; the floor is their maximum per engine.

(a) THE CSS THE BUILD EMITS — BINDING.
    Tailwind v4 compiles every stylesheet through its bundled Lightning CSS
    against targets HARD-CODED in @tailwindcss/node. Nothing configures them and
    nothing (browserslist included) overrides them, so they are the true floor of
    the shipped stylesheet:

    $ grep -o "targets:{[^}]*}" node_modules/@tailwindcss/node/dist/index.js
targets:{safari:16<<16|1024,ios_saf:16<<16|1024,firefox:8388608,chrome:7274496}

    Lightning CSS packs a version as major<<16 | minor<<8 | patch:
      safari   16<<16|1024    =   1049600 -> 16.4.0
      ios_saf  16<<16|1024    =   1049600 -> 16.4.0
      firefox  8388608        =   8388608 -> 128.0.0
      chrome   7274496        =   7274496 -> 111.0.0

    -> chrome 111 · firefox 128 · safari 16.4 · ios_saf 16.4.
    Corroborated in the emitted CSS itself, which carries the features those
    numbers exist for (counts off web/frontend/dist/assets/*.css at this HEAD):
      @property        42 occurrences
      color-mix(       70 occurrences
      :has(             8 occurrences
      dvh               8 occurrences
    @property is Chrome 85 / Safari 16.4 / Firefox 128; color-mix() is Chrome 111 /
    Safari 16.2 / Firefox 113. Their per-engine maxima ARE the Lightning targets.
