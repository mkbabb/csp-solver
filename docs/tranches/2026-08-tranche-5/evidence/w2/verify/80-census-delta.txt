2.1a/c/d — WHY THE RAW PROBES READ 1 / 1 / 2, AND WHY ALL THREE ARE GREEN
══════════════════════════════════════════════════════════════════════
The charter's 2.1a filter is `grep -vc "^\s*\*\|//"` applied to `grep -rn` OUTPUT.
`grep -rn` prefixes every line with `path:lineno:`, so the `^\s*\*` alternative anchors
against the PATH, never against the comment marker — it can match nothing, ever. Only the
unanchored `//` alternative fires. A block-comment `*` line therefore always survives the
filter. This is a probe defect, not a surviving reference.

  $ grep -rn "gameRegistry" web/frontend/src | grep -v "\.test\.ts" \
      | grep -vcE "^[^:]+:[0-9]+:[[:space:]]*(\*|//|/\*)"     -> 0
  the one raw hit: src/games/cards.ts:4 — past-tense prose in the header naming the table
  it replaced. Code rows: 0.
