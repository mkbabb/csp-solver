## 3 · ORDER 3 — THE 45.33 / 31.73 SLACK, RECONCILED ON ONE ARM (A5-G4)

`logs/A6-10-referent-arm.log` · `rig/ribbon-referent-arm.mjs` · chromium/light/320, built dist,
DPR2, one run, one tree.

**The hypothesis was stated before the run, off the arithmetic alone**: 45.33 − 31.73 = **13.60**
and 45.34 − 31.74 = **13.60** — the same constant on both sides, which is what a padding offset
looks like and what a tree move or a font swap does not. `.guard-note`'s rule is
`padding: 0.75rem 0.85rem 0.9rem` — 0.85rem × 16 = **13.60px** — and it is byte-identical at **all
four** pass-4 Lane-A commits (`94ce993e`, `c6eda619`, `3969f512`, `236d22fe`) and at `abe533c4`
(`GameGallery.vue:853-861`; `:762-770` at the pass-4 tree). The offset is not a coincidence of one
checkout.

**The arm reads both referents off the same rect, for all three shipped sub-lines:**

```
"your marks aren't saved"          note 255.83×106.2  lines 1  border 65.56/65.58  content 51.96/51.98  pass4 51.96/51.98
"kenken's marks aren't saved"      note 255.83×106.2  lines 1  border 55/55        content 41.4/41.4    pass4 41.4/41.4
"neither board's marks are saved"  note 255.83×106.2  lines 1  border 45.33/45.34  content 31.73/31.74  pass4 31.73/31.74

RECONCILIATION GATE — pass 4's 320 row reproduces on the CONTENT referent (±0.05px), all three: PASS
FALSIFIER      — the same comparison on the BORDER referent must NOT pass: PASS (it reds, as it must)
IDENTITY       — border − content == the note's own padding, both sides, all three:            PASS
```

**THE RULING: neither figure is struck. Both are the same measurement, under two referents.** Pass
4 measured the sub-line against the note's **content** box; pass 5's re-authoring measured it
against the **border** box; the gap is `.guard-note`'s own 13.60px of horizontal padding, a
constant that cannot depend on the string — and does not, across three strings spanning **20.23px**
of slack (51.96 − 31.73, re-derived). The `slack[text]` column disambiguates the referent rather
than assuming it: the `<p>` reads
0.14/0.16 and 0/0 against the sub, so the text block fills the content box and "content box" and
"the block the sub lives in" are one referent, not two candidates.

**"Two trees and two instruments apart" is refuted as the explanation.** The tree moved twice
(T5-W2 `74b2835d`, T5-W3 `9061b8c1`, both touching this component) and moved this number by
**zero**; the instrument was re-authored and reproduces three cells to the hundredth. What was
offered as a reconciliation named two axes that are both null.

**The arm carries its own falsifier**, per the standing law: the identical comparison is re-run on
the border column and MUST red, and the rig exits non-zero if it does not. A rig where both columns
pass is a rig that cannot tell the two referents apart, and it says so on its own gate line.

**BORN-RED, banked** (`A6-11`): `ABLATE=padding` drops the one term the whole reconciliation rests
on — the content referent stops subtracting the note's padding — and both gates go red on the same
run, `EXIT=1`, with the reads themselves unchanged. Restored: `A6-12`, `EXIT=0`. The gate is known
to be able to fail, on the term it is about.

**What each pass must now write.** The slack is quoted with its referent named or not at all —
`31.73px content-box` and `45.33px border-box` are both true of the same shipped ribbon, and
neither sentence is complete without the noun.
